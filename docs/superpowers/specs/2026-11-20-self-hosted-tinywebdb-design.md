# 自建公网排行榜服务设计

## 目标

用自己的公网服务替换第三方 TinyWebDB，让游戏排行榜继续支持多设备、多玩家共享，并由项目维护者控制数据存储。

## 方案

新增一个 Python 标准库服务 `server/leaderboard_server.py`，使用 SQLite 持久化数据，提供与当前前端兼容的 `POST /api` 接口。服务实现 `update` 和 `search` 两个动作，并返回 TinyWebDB 风格 JSON。前端把 API 地址改为部署后的自有域名。

## 数据与接口

- SQLite 表保存 `tag`、`value`、`created_at`，`tag` 唯一。
- `update` 写入成绩；服务端校验 tag 前缀、JSON 格式、昵称长度和分数范围。
- `search` 按前缀查询，按创建时间倒序分页，返回 `{tag: value}`。
- CORS 只允许配置的前端来源；健康检查使用 `GET /health`。
- 管理密钥只放服务端环境变量；前端公开的访问凭据只作为兼容层限制，不能视为秘密。

## 部署边界

本次实现包含可运行服务、依赖/启动说明和前端接口配置，但真正公网可访问还需要一个云服务器或托管平台、持久化磁盘和域名（可先使用平台分配的 HTTPS 域名）。没有这些账号或部署权限时，只能完成可部署代码，不能代替用户创建云资源。

## 验证

先用测试请求验证 `update`、`search`、分页、前缀隔离和非法输入；再本地启动服务，连接游戏前端完成一次提交与读取；最后检查 HTTPS/CORS 配置说明。
