# 静态文件排行榜设计

## 目标

移除 TinyWebDB 网络依赖，让游戏在离线或纯静态托管环境中运行排行榜。

## 方案

新增 `v1/leaderboard.json` 作为初始榜单文件。排行榜脚本读取该文件，并合并当前浏览器 `localStorage` 中的本地成绩；提交成绩时只写入当前浏览器的本地存储，不发起网络请求。

## 数据行为

- JSON 文件保存可随项目发布的初始记录。
- 本地记录保存于 `localStorage` 的独立键中，限制为最近 20 条。
- 展示时合并两类记录，按提交时间取最近 20 条，再按分数降序显示。
- 断网、`file://`、GitHub Pages 均可用。
- 不同浏览器、设备和用户之间不共享新增成绩；需要共享时必须改用服务端方案。

## 影响范围

- 修改 `v1/leaderboard.js` 的读取、提交和错误处理流程。
- 新增 `v1/leaderboard.json`。
- 保留昵称的 `localStorage` 键和现有排行榜界面。
- 更新 `README.md`，说明数据位置、清空方法和共享边界。

## 验证

使用 Node 运行排行榜相关测试，并在本地静态服务器和 `file://` 场景确认：加载初始榜单、提交本地成绩、刷新后仍存在、网络不可用时不报错。
